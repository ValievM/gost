# Генерация DOCX-отчёта с AI

Инструкция для Claude и других агентов, которые получают ссылку на репозиторий
и должны вернуть готовый `.docx`.

## Что прочитать

Обязательно:

1. [README](../README.md) — установка и общая модель;
2. [модель DOCX](docx/README.md) — конвейер и инварианты;
3. [полный пример](../examples/docx/full-report.cjs) — основной шаблон.

Только при необходимости:

| Задача | Документ |
| --- | --- |
| Найти сигнатуру или опцию | [DOCX API](docx/api.md) |
| Текст, списки, код, приложения | [Контент](docx/content.md) |
| Таблицы и Office Math | [Таблицы и математика](docx/tables-and-math.md) |
| PNG или PlantUML | [Изображения и диаграммы](docx/images-and-diagrams.md) |
| Титульник, стили, секции | [Документ и стили](docx/document-and-styles.md) |
| Разобрать предупреждение | [DOCX lint](docx/lint.md) |

Не читать Excel-документацию, если XLSX не входит в задачу.

## Алгоритм

1. Использовать Node.js 18+ и установить пакет:
   ```bash
   npm install github:Magomed-cmd/gost
   ```
   Канонический пример написан на CommonJS; ESM `import` также поддерживается.
2. Составить структуру отчёта и подготовить фактический текст, таблицы, формулы
   и изображения. Не выдумывать результаты расчётов и источники.
3. Создать один экземпляр `g = createDocxGost()` и отдельные счётчики рисунков
   и таблиц.
4. Собрать один плоский массив `children`. Результаты `list`, `codeBlock`,
   `codeFile`, `appendix` и `diagramBlock` добавлять через spread.
5. Для каждого объекта соблюдать порядок:
   - таблица: ссылка в тексте → подпись → таблица;
   - рисунок: ссылка в тексте → изображение → подпись.
   Если асинхронный `diagramBlock()` создаётся заранее, сохранить номер через
   `const number = figures.peek()` до его вызова: создание подписи сразу
   увеличивает счётчик.
6. Выполнить `g.lint(children)`. Не выдавать документ с `warn`; исправить
   причину, а не скрывать вывод.
7. Собрать титульную и содержательную секции, затем сохранить `.docx`.
8. Проверить, что файл существует и не пуст. Отрендерить его в PDF/PNG через
   Word, LibreOffice или доступный DOCX renderer и просмотреть все страницы.
9. Исправить обрезание, переносы, пустые страницы и разрыв объектов с
   подписями. Повторять рендер до чистого результата.

## Обязательные инварианты

- Использовать `@magomed-cmd/gost/docx`, а не внутренние файлы `dist`.
- В репозитории примеры подключают `../../dist/*` только для локального запуска.
- Заголовки создавать через `h1/h2/h3`: так их видит оглавление Word.
- `makeTitlePage()` предназначен для ИТА ЮФУ в Таганроге.
- Ширины таблиц задаются в DXA; сумма стандартных колонок — `9355`.
- Авторазмер без явных `width/height` поддерживает PNG. Для JPEG задавать
  размеры и `imageType: "jpg"`.
- Не ставить `pageBreak()` первым, последним или сразу после заголовка.
- Не оставлять `placeholder()` в готовом отчёте.
- DOCX lint проверяет структуру, но не фактическую пагинацию и не доказывает
  соответствие ГОСТ.
- Поле оглавления обновляется Word при открытии; перед сдачей проверить его
  обновление в редакторе.

## PlantUML и Java

`diagramBlock()` требует Java. Перед запуском проверить:

```bash
java -version
```

Если Java недоступна, нельзя оставлять пустое место или placeholder. Нужно
отрендерить диаграмму другим доступным способом в PNG и вставить её через
`imageBlock()`, сохранив ссылку в тексте и подпись.

## Частые ошибки

| Ошибка | Исправление |
| --- | --- |
| В `children` попал вложенный массив | Добавить `...g.list(...)`, `...g.codeBlock(...)` и т. п. |
| Рисунок без подписи | Сразу после `imageBlock()` вызвать `figures.caption()` |
| Подпись таблицы снизу | Перенести `tables.caption()` перед `makeTable()` |
| Ссылка на рисунок на единицу больше | Сохранить `peek()` до раннего вызова `diagramBlock()` |
| JPEG передан в авторазмер | Задать явные размеры и `{ imageType: "jpg" }` |
| Оглавление пусто в просмотрщике | Открыть документ в Word и обновить поля |
| Java отсутствует | Подготовить PNG отдельно и использовать `imageBlock()` |
| Lint прошёл, но вёрстка сломана | Выполнить обязательный визуальный рендер |

## Критерии готовности

- скрипт завершается с кодом `0`;
- DOCX lint не содержит `warn`;
- `.docx` создан и открывается;
- все заголовки попадают в обновлённое оглавление;
- номера ссылок совпадают с подписями;
- таблицы, формулы, изображения и листинги читаемы;
- нет пустых страниц, обрезания и разрыва рисунка или таблицы с подписью;
- итоговый файл, а не только исходный `.js`, возвращён пользователю.
